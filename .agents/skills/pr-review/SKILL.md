# PR 审查

1. 对照工单：PR 是否只做了工单里写的，验收步骤能否做到。多做的部分要求删掉。
2. 自己读一遍改动，重点看：
   - 会不会坏功能、卡死、取消后状态错乱。
   - 记忆、聊天、配置会不会丢或被覆盖。
   - 花费上限能不能被绕过，请求会不会重复发。
   - 有没有提交密钥、人设正文、真实聊天；工具有没有越权；一个角色能不能读到另一个角色没分享的记忆。
3. 小兔子的意见：只修上面这几类问题。其余在原评论下回一句“不改，原因：…”，然后标记已解决。不追风格建议。
4. CI 红了先修，绿了再请 lan 验收。
5. 审查结论写在 PR 评论里：能合并 / 要改什么（逐条，带文件位置）。
