# 工单 060：Ombre 运行期生命周期与安全恢复

## 目标

Ombre 在 VEIL 运行期间退出或 MCP 连接失效后，Peter 能在确认正确实例并验证只读记忆能力后恢复服务；结果不明的写入和检索不自动重放。

## 当前状态

- 基于 main `560bf6028dd5bc4b912c54eb8f50c01d76ed1602`。运行期恢复由现有 `memory_agent.MCP` 单线程队列协调，复用 `ResidentProcess`、角色 vault 锁和 Ombre 配置，不新增通用服务管理框架。
- 服务启动与恢复检查 HTTP、角色进程元数据及 vault 锁，再用当前角色 token 初始化 MCP、核对核心工具并调用只读 `pulse`。不信任单独的 `/health`，身份或端口不明时拒绝接管。
- 每次请求最多一次恢复；每个 MCP 生命周期最多两次恢复，重启等待有上限。只恢复本 VEIL 持有的宿主；正常关闭后不再启动。`hold`、`breath_search` 和其他非 `pulse` 调用不重放，写入结果不明时保持未确认。
- 已复用仓库锁定的 Ombre 3.6.14（上游提交 `115d831d979bf67efc7150f976e2cb34c333c935`，MIT）及现有 MCP SDK 1.30.0。上游提供 token 认证、Streamable HTTP、MCP 工具和 O(1) `/health`；没有运行期进程恢复，因此 VEIL 用现有 host/lock 承担进程恢复，并以官方 MCP SDK 验证实际工具。没有复制上游实现。
- 固定 Ombre 临时 vault 的真实子进程恢复、并发请求、检索恢复和丢失 `hold` 回执后不重放均通过；完整离线套件 332 项通过、3 项跳过，真实生命周期集成 1 项通过。Lan 的 Windows 体验验收仍待完成。

## 验收步骤

1. 启动隔离虚构角色并确认一条虚构记忆可检索；用测试入口终止该测试实例的 Ombre 子进程，确认 Peter 无需整体重启 VEIL 即恢复检索。
2. 同时从聊天和自主活动发起记忆调用，再模拟恢复失败；确认只恢复一个 Ombre 实例，失败有界且文件工具仍可用。
3. 模拟写入已保存但回执丢失，恢复后核实虚构记忆仅有一条；确认没有碰到真实角色记忆或正在运行的 Ombre。
