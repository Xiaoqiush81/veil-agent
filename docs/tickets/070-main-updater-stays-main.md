# 工单 070｜Windows 更新后留在 main

## 目标

Lan 双击 `update-main.cmd` 后，运行目录停留在刚更新完成的 `main`，避免随后启动 Peter 时又运行旧工单分支的代码。

## 根因与范围

工单 065 为保护开发分支，成功更新 main 后会自动切回启动更新器时所在的分支。这个行为适合开发工作树，却不适合 Lan 的运行目录：更新器明明显示成功，随后 `start-web.bat` 仍可能从旧 ticket 分支启动。

本工单只调整成功路径。更新成功后保留在 main，并显示明确提示；工单分支及其提交不会被删除。若更新在 ignored 文件碰撞等安全检查处失败，仍返回原分支并保持原有恢复语义。本工单不改变 stash、恢复分支、快进限制或 ignored 文件保护。

## 验收步骤

1. 在非 main 分支双击 `update-main.cmd`，确认更新成功后显示留在 main 的提示。
2. 关闭窗口后运行 `git branch --show-current`，确认结果为 `main`；再启动 Peter，使用的是刚更新的 main。
3. 再运行一次更新器，确认仍停留在 main；若模拟 ignored 文件碰撞，确认更新失败、文件未覆盖且返回原分支。
