# 工单 058｜记忆检索分支隔离与安全诊断

## 目标

Lan 能在正常聊天中继续获得已确认可见的记忆；某一检索分支失败时能知道失败阶段，且隐藏或未确认记忆不会进入 Peter 的上下文。

## 当前状态

`memory_agent.py` 的 `Memory.context()` 将 `breath_search`、`feel`、自动召回可见性复核和开场可见性复核放在同一个 `except` 中，任一异常都会清空本轮 recall，提示也没有阶段信息。Lan 的实时截图显示 `breath_search` 的结果未确认，随后可重试只读 `pulse` 重连后仍连接不可用；加上自主活动里的 `hold`/`breath_search` 同时失败、文件和长期任务工具成功，已确认故障在 Ombre MCP 连接/服务路径而非某条记忆的可见性或聊天界面。未读取私人诊断，不能进一步归因给 embedding、服务端或供应商。复用现有本地 `diagnostics.jsonl` 和 unittest；已按 reuse-first 查阅 Ombre 现有检索契约，但 GitHub 在本窗口 DNS 不可达，且这不是可由通用库替代的角色隔离、隐藏保护接线。

## 验收步骤

1. 用隔离虚构角色创建一条可见和一条隐藏记忆，正常聊天确认 Peter 能自动使用可见记忆，不能说出隐藏正文。
2. 人为让情感检索或一条可见性检查失败，确认聊天说明安全阶段，其他已确认可见记忆仍可用。
3. 检查该角色的 `memory/_agent/diagnostics.jsonl`，确认只有失败阶段和错误类型，不含聊天内容、查询、记忆正文或密钥。
