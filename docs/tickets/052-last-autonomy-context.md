# 工单 052：最近一次自主活动持续上下文

## 目标

Lan 在任何正常聊天后询问 Peter 上次自主活动做了什么，Peter 都能依据界面同一份最近记录准确回答，并知道它是过去的执行记录而非当前状态。

## 当前状态

界面详情和 `data/<角色>/autonomy.jsonl` 已保存最近一次完成活动；042 只在第一次成功聊天交接后以确认日志阻止其再次进入模型上下文。052 复用该原始记录、`Chat.send(extra_context=...)` 和 042 的确认日志：确认日志仍保存首次交接事实，但不再决定记录能否持续提供。所有新增模型提示包裹文字为英文，以 `System record | Last autonomous activity | Occurred at:` 标记来源与时间；原记录中的事实值保持原样，不用猜测翻译。复用检查：查阅 durable-acp 的 append-only journal / snapshot 做法，以及 Cloudflare Agents 的持久会话与上下文块做法；它们支持“持久事实、紧凑投影、每次请求注入”的原则，但引入运行时或数据库超出本地 JSONL 单记录范围，因此不复制代码、不新增依赖。

## 验收步骤

1. 用虚构角色完成一次自主活动，正常聊天多轮后问 Peter “What did you do the last time you woke up?”；对照页面“上次自主活动详情”，确认时间、工具、结果和结束原因一致。
2. 让该记录含一个虚构工具失败；确认 Peter 将它称为上次活动的历史结果，而不是说故障仍在发生；问当前是否仍失败时，他应说明需要重新核实。
3. 重启服务并完成一次新自主活动；分别在聊天和下一次自主唤醒后确认 Peter 只引用新的最近记录。
